# Staff operations panels

Deploy the matching `worker.mjs` in Cloudflare first, keeping existing bindings and secrets. Run `install-operations.sh FULL_COMMIT_SHA` as root on the existing reader server. It tests the staged code and previews a read-only summary as the publisher account before installing. The VSTP reader and publisher restart; Darwin, Gemini and TRUST readers and the abandoned TD services are not changed. GitHub Pages publishes the frontend.

The existing 120-second allocation snapshot carries a bounded `operations` object. There are no extra KV writes, keys, browser polls or endpoints. At most 30 latest VSTP schedule variants are listed, changed within 48 hours and running today or tomorrow. The overview is not a complete event audit. Optional summaries are dropped first if the upload approaches its size limit.

`vstp_changes` is created by the VSTP reader at startup. It retains the latest transaction action and last captured Victoria route per variant, in the same transaction as the raw message and schedule projection. Duplicate/older messages cannot rewrite it. Orphan audit rows are pruned alongside expired schedules. Existing states without an audit row are labelled Captured, not assumed new. Deletions withdraw a VSTP variant; only an STP C variant is labelled cancelled. Daily timetable comparisons are labelled separately from previous captures. Off-station changes and national schedules without evidence of a Victoria visit are excluded. The old/current times are working times and use H for a half minute internally. Booked days shown are origin operating dates.

A stale or blocked VSTP feed leaves the last captured summary visible with a warning. Feed health displays the Darwin board time, Gemini publisher sync/reader state, TRUST last batch, VSTP last successful broker catch-up and daily extract time. These are feed indicators, not guarantees for every service. The VSTP summary remains independent of Gemini allocation availability.

Turnaround links require unique matches for both ends, within two hours, from a complete matching Gemini unit set or the same UID and operating date. Through calls, cancellations, diversions, conflicting supplied unit sets and ambiguous pairings are withheld. West Turnback returns use an exact timed Victoria call from the fresh operational route. When unit evidence is unavailable, a unique arrival/departure pair on the same exact platform and operator within 90 minutes is shown as a possible pairing, based only on platform and timing. Supplied conflicting unit sets still prevent a suggestion. No link is presented as a confirmed stock diagram. A missing service outside the board window cannot be linked.

Carriage counts remain feed-supplied. There are no staff-entered booked-count references or booked-versus-actual formation warnings. Darwin/Gemini differences remain labelled as feed differences.
